# 演示与验收

已生成 deliverables/演示视频.mp4，总长 170 秒。画面来自官方 Burger 的实际 Gazebo/RViz 运行，包含开环、点控制、航点、避障和完整迷宫过程；每段注明倍速，中文旁白由 espeak-ng 合成。原片和处理说明位于 results/gazebo_gui。

## 三分钟安排

| 时间 | 画面与动作 | 讲解要点 |
|---|---|---|
| 0 至 15 秒 | Docker 环境、Gazebo 与 RViz 同屏 | 宿主 Ubuntu 24，容器 Ubuntu 22.04、Humble、Classic 11 |
| 15 至 35 秒 | 预先录制的直行、原地转向、点控制或航点片段 | 开环与里程计闭环的区别、到点停车 |
| 35 至 45 秒 | 雷达点云、wall_distances、控制状态 | 前左三区提取与无效值处理 |
| 45 至 170 秒 | 完整迷宫行驶，从入口到出口，必要时连续倍速 | 左手优先、过角与转向闭环、自适应减速 |
| 170 至 175 秒 | 出口 DONE 与零速度 | 真实耗时、结果与局限 |

若迷宫全过程超过时间预算，先完整录制，再对连续过程倍速，明确注明倍速，保留完整原片。不要剪掉碰撞或失败来声称一次成功。讲解可以后期配音，所有展示的数据来自实际运行。

参考口述：本项目运行在 Ubuntu 22.04 的 Docker 容器内，使用 ROS2 Humble 和 TurtleBot3 Burger。Gazebo 计算物理与激光，RViz 显示模型、扫描和轨迹。机器人根据里程计执行点控制，根据雷达提取前、左、右距离。左墙跟随遇到左侧开口时先越过墙角再转向，前方封闭时右转，转角由里程计闭环完成。自适应策略根据前方净空和角速度减速。现在机器人抵达出口，控制器进入 DONE 并持续发送零速度。最终耗时和碰撞情况以本次实际 CSV 与录像为准。

## 录制方法

GUI 启动：

```bash
bash tools/docker.sh wall
```

宿主机 X11 桌面可用：

```bash
bash tools/record_demo.sh demo.mp4
```

默认分辨率为 1920×1080，包含 PulseAudio 默认录音输入，最长 175 秒。按实际显示器设置 RESOLUTION。需要先录完整原片可设置 DURATION=400；不录音可设置 RECORD_AUDIO=0。

```bash
RESOLUTION=1920x1080 DURATION=400 RECORD_AUDIO=0 bash tools/record_demo.sh raw.mp4
```

Ubuntu 24 常用 Wayland。Wayland 桌面下用系统录屏或 OBS；容器 GUI 通过 XWayland 显示，不意味着 x11grab 一定能录到整个桌面。任务录制在宿主机进行，不需要把麦克风设备交给容器。

## 验收准备

1. visual、collision、inertial 分别影响什么：显示、碰撞、质量与惯性，彼此不能互相替代。
2. RViz 与 Gazebo 的区别：RViz 显示话题与 TF，Gazebo 执行动力学和传感器仿真。
3. 为什么把角差限制在 ±π：避免跨越角度边界时走长方向。
4. 为什么大角差时先原地转向：减少横向误差和绕圈。
5. 如何找到左侧扫描点：用 angle_min + i × angle_increment 计算角度，再判断与 π/2 的环绕角差。
6. 无穷大、NaN 怎么处理：正无穷当作量程内无障碍，NaN 舍弃；整个分区无效时停车。
7. 为什么雷达采用传感器 QoS：兼容常见 best effort 传感器发布端。
8. 为什么左开口先前进再左转：使机器人中心越过角点，减少撞内角风险。
9. 左墙跟随是否适合所有迷宫：不保证处理所有拓扑，存在孤立墙岛、环路等限制。
10. 自适应速度是否一定更快：不是；本次离线结果耗时更长，最小安全余量更大。
11. Docker 是否把宿主机变成 Ubuntu 22：宿主不变，容器内用户空间为 22.04，并共享宿主内核。
12. 目前哪些结论是真实验证的：本机编译、自动化测试和离线运动学实验；Docker 构建与官方模型 Gazebo 实测也已完成，数据见 results/gazebo。
